# Backend error audit — 16 November 2026

A static audit of the Laravel 12 backend (`backend/`) covering the route/controller layer, middleware, service layer, reporting pipeline, jobs, MCP/AI integration, configuration, and migrations. Every file in `app/`, `routes/`, `config/`, and the migrations was read in full; each finding below is backed by code verified in place. Remediation is recorded in [019 — Backend error audit remediation](../../changes/iteration-03/sprint-03/019-backend-error-audit-remediation.md); M02 remains deferred to product policy.

## What was executed

| Check | Command | Result |
| --- | --- | --- |

| Backend test suite | `php vendor/phpunit/phpunit/phpunit` (PHPUnit 11.5.57, PHP 8.5.12) | OK — 101 tests, 788 assertions, 1 skipped |

The single skipped test is `tests/Feature/PublicDemoProvisioningTest.php:87`, the explicitly gated isolated MySQL provisioning test. This is intentional, not a defect.

## Headline result

**No critical or high-severity defects were found.** Authorization, ownership, office scope, evaluation uniqueness, export privacy, CSRF compensation, MCP bearer gating, and secret handling all verified sound. The findings below are availability, performance, audit-classification, and unresolved-policy issues.

## Medium findings

| M01 | Requests | N+1 query fan-out in list rendering: `present()` re-runs the authorization scope plus four lookups and an evaluation check per row. | `app/Services/RequestReader.php:28` mapping to `app/Services/RequestAccess.php:21-35`; same pattern in `RequesterDashboardService`. | A 20-row page issues roughly 130 queries; dashboard scales the same. | M02 | Workflow | Requests in "For Clarification" are a dead end if the requester never responds: only the requester may move it to Pending (admins are explicitly blocked) and the transition map contains no cancelled/withdrawn/terminal state. | `config/workflow.php:5-12`; `app/Services/RequestWorkflow.php:87`. | Abandoned requests stay open forever, distorting office metrics, with no administrative escape. | M03 | Reports | Queue `retry_after` (120 s) can expire mid-render: `GenerateReport` declares no `$timeout` and no backoff, and its re-entry guard treats only `completed` as in-flight. | `config/queue.php:2`; `app/Jobs/GenerateReport.php:12-16`. | A large render exceeding 120 s becomes visible again and a second worker re-executes it concurrently, racing file writes to `reports/{id}.{format}` and status updates. | Set `$timeout` above worst-case render time, raise `retry_after` above it, add `backoff()`, and guard against re-entry while `processing` (or use unique-job locking). |

## Verified sound (highlights)

The full review confirmed the domain rules from the repository guidance hold in the implementation:

- **Authorization and scope.** No IDOR on `requests/{id}`, `notifications/{id}/read`, `feedback/{kind}/{id}`, or `reports/{id}`/`/download` — every record resolves through the scoped query (`RequestAccess::scope/authorize`), and downloads additionally verify role, office, ownership, status, exact private-path equality and file existence before streaming. Office membership alone grants no university-wide reads anywhere.
- **Lifecycle integrity.** ULID job numbers inside the create transaction with a unique index; optimistic concurrency via `record_version` under `lockForUpdate`; all writes commit events/revisions/assignments/audits/notifications in one transaction; clarification and resubmission preserve identity, job number and revision history; completed requests are immutable and completion requires an outcome plus an active assignment.
- **Evaluation rule.** One evaluation per completed request, by its authenticated owner, enforced with a row lock, an existence check, and `service_evaluations.request_id` as the primary key.
- **Privacy.** Internal notes stay internal (`visibility='requester'` filtering for requesters, notifications never copy internal message text); general feedback stays independent of verified evaluations; an entered public job number is search text only, never joined to private records.
- **Exports and injection.** Exports on the private local disk with fixed paths, CSV/Excel/PDF formula-injection guards, fully escaped Blade output, dompdf remote/JS/PHP execution disabled and chroot-limited; `download_url` only when completed and the file exists on disk.
- **MCP boundaries.** Bearer-only transport with HTTPS and origin checks, expiring scoped tokens mapped to authorization rows, tool scope enforced at three independent layers, office/record scope re-checked per tool, read-only tool set, no secrets in logs or audit rows, invocation audit with stale-row reconciliation.
- **Hardening.** Session-guard API with CSRF exemption compensated by trusted-origin/JSON/Sec-Fetch-Site checks; login throttling keyed by IP and account; password re-confirmation for key/client mutations; encrypted provider key never returned; deactivated accounts logged out on every request; production misconfiguration fails closed at boot.

## Review boundaries

- This was a static audit plus the commands listed above. It did not load-test the queue concurrency claim (M03), measure real query timings (M01/M05), or exercise a split-origin browser preflight (M06) — each is supported by code reading and should be confirmed by reproduction when fixed.
- The API returns no record content from MCP write paths because the first release registers read tools only; write-path service spread (L03) is a latent risk for the deferred operational writes, not a current exposure.
- M02 involves an unresolved product policy (administrative escape from "For Clarification"); AGENTS.md explicitly reserves such transition decisions and forbids inventing them in code.
